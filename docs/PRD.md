# Claude Code 작업 지시서 — N-BOX Speed Match 3D MVP

당신은 프론트엔드 게임 개발자이자 3D 인터랙션 디자이너다. 현재 연결된 GitHub 저장소에서 기존 `nbox_speed_match_mvp.html`을 먼저 읽고, **기존 동작을 보존하면서** React + TypeScript + Vite + React Three Fiber(Three.js) 기반의 완성도 높은 웹게임으로 리팩터링하라. 질문 없이 임의로 게임 규칙을 변경하지 말고, 필요한 세부 구현은 합리적으로 결정해 진행하라. 파일이 저장소에 없으면 사용자에게 제공된 HTML을 프로젝트 루트의 `reference/nbox_speed_match_mvp.html`에 두고 참고하라.

## 0. 먼저 해야 할 일
1. 저장소 구조, 기존 HTML/CSS/JS와 현재 실행 환경을 확인한다.
2. 기존 코드에서 음료 데이터, 정답 생성, 자동 판정, 클릭 선택/교환, 타이머, 라운드 진행, 정답 공개, 최고 기록 저장 로직을 분석한다.
3. 구현 계획을 짧게 제시한 뒤 실제 파일을 생성·수정한다. 설명이나 목업만 만들고 멈추지 않는다.
4. 변경 후 빌드, 린트/타입 검사, 주요 게임 로직 테스트를 실행한다. 실행하지 못한 검증은 명시한다.

## 1. 제품 개요
- 게임명: N-BOX Speed Match — Korean Drinks Edition
- 핵심: 숨겨진 정답 캔 배열을 추리하면서 3-Box → 4-Box → 5-Box를 연속으로 최대한 빨리 클리어하는 1인용 웹 미니게임.
- 대상: 모바일/데스크톱 브라우저 사용자. 별도 회원가입이나 튜토리얼 없이 바로 플레이 가능해야 한다.
- 레퍼런스 분위기: https://x282665.com/games/turkish-ice-cream-3d/ — 가벼운 3D 플래시게임 같은 물체감과 직접 조작의 손맛. 레퍼런스의 캐릭터·에셋·코드를 복제하지 않는다.
- 기존 HTML의 게임 규칙과 콘텐츠를 source of truth로 사용하되, 아래 명세와 충돌하면 아래 명세를 우선한다.

## 2. 확정된 게임 규칙 (변경 금지)
- 라운드: 3개 → 4개 → 5개 캔을 **연속**으로 맞힌다.
- 타이머: **00:00.00부터 증가**하는 스톱워치. 60초 제한이나 실패 타이머 없음. 시작 시 작동, 라운드 전환 시 계속, 마지막 5-Box 클리어 즉시 정지. `performance.now()` 기반으로 실제 경과 시간 계산.
- 음료 풀: 아침햇살, 초록매실, 갈아만든배, 비락식혜, 솔의눈. 3/4-Box에서는 5종 중 중복 없이 선택, 5-Box에서는 5종 모두 사용. 라운드마다 정답 순서는 무작위.
- 처음부터 끝까지 **클릭 앤 클릭** 방식만 사용한다. 드래그앤드롭은 제거한다.
  1) 초기: 트레이의 캔 클릭 → 위쪽 박스의 빈 슬롯 클릭 → 배치. 선택한 캔은 살짝 위로 들리고 하이라이트된다.
  2) 모든 슬롯이 채워지면 즉시 자동 판정한다.
  3) 이후: 박스의 캔 A 클릭 → 캔 B 클릭 → 두 캔의 위치를 **서로 교환**하고 이동 애니메이션 완료와 함께 자동 판정한다.
  4) 같은 캔 다시 클릭 시 선택 취소. 첫 배치 중 배치한 캔을 빈 슬롯으로 옮길 수 있다.
  5) 캔 선택·교환에 별도의 CHECK 버튼을 두지 않는다.
- 판정: `playerOrder[i] === answerOrder[i]`인 슬롯 수만 센다. 어느 슬롯이 맞았는지는 보여주지 않는다.
- 피드백: 캔이 놓인 게임판 **중앙에 오버레이**로 `2 RIGHT!`처럼 맞은 개수만 표시. 분모, `KEEP MATCHING` 등 부가 문구 금지. 밝고 불투명한 아이보리/오프화이트 알림 배경, 읽기 쉬운 진한 글씨, 0.7초 표시 후 사라짐. 입력을 막지 않는 `pointer-events: none`. 연속 변경 시 이전 타이머/애니메이션을 정리하고 최신 결과만 보여준다.
- 정답: 게임판 **아래**에 실제 정답 캔들이 놓여 있고, 그 앞에 가림판이 있는 공간 구조. 플레이 중에는 가려져 있으며, 라운드 성공 즉시 가림판이 열려 **정답 순서의 캔 이미지/3D 캔**을 직관적으로 보여준다. 성공 피드백과 짧은 공개 연출 후 다음 라운드로 전환. 마지막 라운드에서는 타이머를 즉시 정지하고 결과를 보여준다.
- RESET: 현재 라운드 캔 배치만 비우고 캔을 트레이로 복귀. 정답 배열, 누적 시간, 이전 라운드 기록은 유지. 현재 라운드의 선택 상태는 해제. 전체 재시작과 혼동되지 않게 라벨 명확히.
- RESTART/PLAY AGAIN: 3-Box부터 새로운 정답으로 전체 재시작. 진행 중 재시작은 확인을 받는다.
- 결과: 총 클리어 시간, 라운드별 소요 시간, 시도/판정 횟수, 개인 최고 기록 표시. 최고 기록은 `localStorage` 저장. 기존 키 `nbox_best_stopwatch`를 가능하면 호환한다.
- 배치가 불완전할 때는 오답 수를 띄우지 않는다. 정답 피드백은 모든 슬롯이 채워진 이후의 유효한 배열 변경에서만 표시한다.

## 3. 디자인 디렉션 — 최우선
**너무 컬러풀하거나 장식이 많은 UI는 금지.** 기존의 하늘·산·나무·구름·캐릭터·패턴 배경·과도한 카드·대시보드형 패널을 되살리지 않는다.
- 단색 웜그레이 또는 부드러운 아이보리 배경 하나. 낮은 채도의 환경광, 자연스러운 접지 그림자.
- 중앙에 실물 비율의 한국 음료 캔과 정면 기반 약한 3D 원근의 진열 박스. 카메라는 거의 정면이며 위쪽 면이 살짝 보이는 정도(예: 작은 elevation angle). 플레이어가 1~5번 위치를 한눈에 구분할 수 있어야 한다.
- 박스는 무채색 흰색/밝은 회색의 **실제 두께가 있는 3D 구조물**. 슬롯 구분이 명확하고, 하단 정답 공간과 가림판이 물리적으로 연결되어 보여야 한다.
- 캔은 실제 한국 제품의 **원래 패키지 디자인**을 반영한다. 기존 HTML에 외부 상품 이미지 URL이 있지만 링크 깨짐, CORS, 저작권/사용권을 검토해야 한다. 가능하면 권한이 확인된 이미지를 프로젝트 `public/assets/drinks/`에 로컬로 두고 캔 표면 텍스처로 매핑한다. **이미지를 확보하지 못했다면 실제 브랜드 패키지를 임의로 재창작했다고 주장하지 말고**, placeholder를 명확히 표시하고 교체 가능한 에셋 구조를 만든다. 외부 URL만을 유일한 표시 수단으로 사용하지 않는다. 로고·이미지 사용권은 공개 배포 전 확인할 수 있도록 README에 남긴다.
- 금속 재질의 윗면/아랫면, 캔 몸통의 원통 형태, 아주 약한 반사광과 광택, 미세한 그림자. 과장된 만화 스타일이나 원색 조명 금지.
- 타이머와 `N RIGHT!`에는 사용자가 요청한 **배달의민족 꾸불림체**를 우선 적용한다. 공식 배포처 및 사용 라이선스를 확인하고 합법적으로 확보 가능한 경우에만 프로젝트에 적용한다. 확보가 불가능하면 유사한 분위기의 라이선스 명확한 폰트로 폴백하고 README에 이유를 적는다. 폰트 파일을 임의의 불확실한 CDN에서 가져오지 않는다.
- 시작 화면 설명은 최대 1~2문장: 예) `캔을 눌러 자리를 맞혀보세요.` / `3 → 4 → 5 BOX, 가장 빠른 기록에 도전!` + `START` 버튼. 긴 규칙 안내, 다단계 온보딩 금지.
- 타이머, 라운드 표시, 리셋/재시작 버튼만 간결하게 배치. 게임 오브젝트가 시각적 주인공.
- 모바일에서 캔이 너무 작지 않도록 적절한 크기·터치 영역을 확보하고, 5-Box에서도 가로 스크롤 없이 슬롯이 모두 보이게 조정.

## 4. 3D 인터랙션 — 이번 개발의 핵심
- React Three Fiber + Three.js 사용. 캔과 진열대는 실제 3D 메쉬(원통, 박스 등)로 구성한다. HTML 요소에 CSS `perspective`만 주는 방식으로 대체하지 않는다.
- 캔 선택: 선택한 캔이 부드럽게 0.1~0.2초간 살짝 위로 뜨고, 크기/광택/약한 외곽 강조로 선택 상태를 명확히 보여준다. 과도한 바운스 금지.
- 트레이 → 슬롯 배치: 캔이 3D 공간에서 들어 올려졌다가 목표 슬롯으로 이동한 후 부드럽게 내려앉는 모션. 위치와 순서를 정확하게 유지.
- 캔 A ↔ 캔 B 교환: 두 캔이 서로 **실제로 이동하는** 트윈 애니메이션. 서로 겹치지 않도록 하나는 살짝 앞쪽/위쪽으로 우회해 이동. 약 0.2~0.35초. 이동 중 중복 입력/상태 꼬임 방지. 판정 결과와 화면 상태 일치 보장.
- 정답 공개: 하단 가림판이 위로 들리거나 옆으로 슬라이드되어 실제 정답 캔 배열이 드러나는 3D 애니메이션. 공개 후 다음 라운드로 넘어가기 전 충분히 식별 가능한 짧은 홀드(기존 약 1.4초를 참고하되 조정 가능).
- 카메라 움직임은 최소화한다. 회전/줌/드래그 카메라 컨트롤은 MVP에 불필요.
- WebGL 지원이 약한 환경에서는 읽을 수 있는 2D fallback 또는 친절한 안내 제공. `prefers-reduced-motion`을 존중한다.
- 3D 좌표와 게임 데이터는 분리한다. 애니메이션이 도중에 중단되더라도 정답 배열·배치 상태가 꼬이지 않아야 한다.

## 5. 추천 구조
- Vite + React + TypeScript
- `@react-three/fiber`, `@react-three/drei`, `three`
- 애니메이션은 `@react-spring/three` 또는 R3F에서 안전하게 사용할 수 있는 동등한 트윈 방식
- UI는 일반 HTML/CSS 오버레이. 스타일은 필요한 만큼만 사용하고 대형 UI 프레임워크는 필수 아님.
- 예시 파일 구조:
  - `src/game/types.ts`
  - `src/game/engine.ts` (정답 생성, 판정, 라운드 진행, 시간 계산)
  - `src/game/drinks.ts`
  - `src/components/GameScene.tsx`
  - `src/components/Can3D.tsx`
  - `src/components/Shelf3D.tsx`
  - `src/components/Hud.tsx`
  - `src/components/MatchToast.tsx`
  - `src/App.tsx`
  - `src/styles.css`
  - `public/assets/drinks/`
  - `README.md`
- 서버 없이 로컬 실행 및 정적 배포 가능해야 한다.

## 6. 버그 방지 및 수용 기준
1. `npm install && npm run dev`로 실행되고 `npm run build`가 성공한다.
2. 첫 라운드부터 드래그 없이 클릭 두 번으로 배치된다.
3. 모든 슬롯이 채워지면 CHECK 없이 자동 판정된다.
4. 캔 두 개를 클릭하면 두 캔이 부드럽게 교차 이동하며 정확히 교환된다.
5. 정확한 개수만 `N RIGHT!`으로 중앙에 0.7초간 표시한다. 틀린 위치/정답은 노출되지 않는다.
6. 정답을 맞힌 즉시 가림판이 열려 아래에 정답 캔 배열이 시각적으로 보인다.
7. 3→4→5 라운드가 이어지고 타이머는 누적된다. 마지막 성공 즉시 타이머가 정지한다.
8. RESET은 현재 라운드만 초기화한다. RESTART는 전체 초기화한다.
9. 새로고침 후에도 개인 최고 기록이 유지된다.
10. 모바일과 데스크톱 모두 조작할 수 있다. 5-Box에서도 클릭 영역이 겹치지 않는다.
11. 기존 음료 5종과 원본 제품 패키지의 식별 가능성을 유지한다. 에셋이 없으면 fallback이 작동한다.
12. 색을 과하게 늘리지 않고 단색 배경, 정면에 가까운 3D 시점, 최소 UI를 유지한다.
13. 핵심 판정 함수와 상태 전환에 대한 단위 테스트를 추가한다. 가능하면 Playwright 등으로 기본 플레이 플로우를 점검한다.

## 7. 작업 결과물
- 실제 작동하는 전체 소스코드를 현재 GitHub 저장소에 작성한다.
- `README.md`에 실행 방법, 프로젝트 구조, 캔 이미지 교체 방법, 폰트/이미지 라이선스 확인 사항, 배포 방법을 정리한다.
- 완료 시 변경 파일 목록, 구현된 기능, 테스트 결과, 아직 해결되지 않은 항목을 간결하게 보고한다.
- GitHub 연결이 되어 있다면 현재 브랜치에서 작업하고 변경 내역을 보여준다. 사용자 승인 없이 `main`에 강제 푸시하거나 기존 작업을 삭제하지 않는다.

**중요:** 기존 HTML을 버리고 새 게임을 임의로 디자인하지 마라. 기존 게임 로직과 UX는 보존하고, 오브젝트 렌더링과 이동/교환/가림판 애니메이션만 진짜 3D로 고도화하는 것이 이번 작업의 목적이다.
